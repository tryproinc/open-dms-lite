- 更新: 2026-11-07
- アプリ識別子: `jp.co.trypro.opendms.lite`。内部のKotlin名前空間は `com.trypro.opendms`
- 対象: Open DMS Lite `0.1.0-lite`(Google Play 公開版と同じ機能)。Full 版から分岐したもので、判定・報知の仕組みは同じ
- 設定の版: `version = day-mvp0-v2`(較正値の互換)/ `settingsSchemaVersion = settings-lite-v1`(保存閾値の互換)
- 位置づけ: **実装の現況を正として書く**。既知の制約は §13 に列挙する
- 数値はすべて**既定値**。閾値設定画面(詳細 → 閾値設定)で変えられる10項目は §12 に示す。
  いずれも製品保証値ではない(`DayMvpSettings` の KDoc に根拠と経緯がある)
- **保安基準・UN-R182/R183 への適合を保証しない**(位置付けは [DISCLAIMER.md](../DISCLAIMER.md)、対応状況は [COMPLIANCE.md](COMPLIANCE.md))
- ソースコメントにある `docs/NN`・`R-NN`・`§14-NN` は、Full 版の非公開の内部資料への参照である(この仕様書が公開版の正)

### Full 版との違い

Lite は、判定・報知・記録を **Full 版と同じ**に保ったまま、次を**ソースごと**取り除いている。

| 取り除いたもの | 内容 |
|---|---|
| 外付けカメラ(UVC) | USB カメラの接続・参考録画・2台構成・主従カメラの選択 |

カメラは**スマートフォンのインカメラ1台だけ**。Lite と Full の機能の比較は、[取扱説明書 §12](USER_MANUAL.md) を参照。

## 1. 全体構成

```
インカメラ(CameraX)
  → MediaPipe Face Landmarker(顔ランドマーク468点・blendshape・頭部姿勢)
  → FeatureFrame(1フレーム分の特徴量)
  → 信号品質の評価(§5)                     … SignalQualityEvaluator
  → 判定入力への変換(較正基準との差分)      … DmsInputMapper
  → 状態機械(閉眼・脇見・こっくり・あくび・監視不能・高温)… DayDmsStateMachine
  → 報知(音・振動・画面)と記録(DB・CSV)

故障監視(フレームが来ない・解析が返らない)は**フレームとは独立した0.5秒周期**で評価する … FaultMonitor
```

- 状態機械は**運行開始のたびに作り直す**(cooldown・継続時間・監視不能状態を前の運行から引き継がない)。例外はあくびの回数(§6.5)
- 判定は `monotonicMs`(端末の単調時計)で行う。発報の記録時刻は壁時計(UTC)

## 2. 用語

| 用語 | 意味 |
|---|---|
| 正規化開眼比 | MediaPipe の開眼度を、開眼較正時の値で割ったもの。1.0 = 較正時と同じ開き |
| 相対 yaw / pitch | 頭部角度から較正時の角度(中央値)を引いたもの。未較正なら絶対角度 |
| validForDecision | そのフレームを判定に使ってよいか(§5)。false のフレームは継続時間に加算しない |
| facialSignalReliable | 表情(開眼度・口の開き)が信頼できるか(§5)。閉眼・こっくり・あくびだけが見る |
| 欠損の猶予 | `qualityGapGraceMs` = **500ms**。条件が途切れてもこの時間以内に戻れば継続とみなす |
| エピソード | 条件が(猶予込みで)途切れずに続いている1区間 |
| cooldown | 同じ種類の警告を一度鳴らした後、再度鳴らさない時間。`alertCooldownMs` = **10秒** |
| 速度ゲート | 脇見を判定する速度の下限。`distractionMinSpeedKph` = **10km/h** |

## 3. 画面状態と運行

### 3-1. 画面状態

| 状態 | 内容 |
|---|---|
| PREFLIGHT(前検査) | 映像・較正状態・音量・速度・取付回転を表示。較正と運行開始を行う |
| CALIBRATING(較正中) | 開眼較正 → 閉眼較正 |
| MONITORING(運行中) | 判定と報知を行う |
| RESULT(結果) | 運行中の発報一覧。CSV 書き出し |

### 3-2. 運行開始の条件

| 条件 | 満たさないとき |
|---|---|
| 較正済み | 「較正開始」ボタンだけが出る |
| メディア音量が最大の **30%以上** | 開始ボタンが押せない。「警告音を試聴」を出す |

顔の大きさが推奨(画面幅の **28%**)未満なら注意文を出すが、開始は止めない。

#### 警告の開始(一度 20km/h を超えるまで待つ)

- 運行開始後、速度が一度 **20km/h** 以上(`armingSpeedKph`)になるまで、故障・高温以外の警告を鳴らさず記録もしない。出発前の準備で手元を見ても鳴らさないため。判定(継続時間の計測)は待っている間も続ける
- 一度始めたら運行終了まで止めない(信号待ちで止めない)
- 待たない: 位置情報が未許可、動作確認モード、**速度不明(§6-2(e))が連続 2分**(`armingNoSpeedFallbackMs`)続いたとき。速度が一度取れた後に測位が途絶えた場合も、途絶えてから 2分で始める(2026-10-18)
- **待っている間に条件を満たした危険状態は、警告を始めた時点で続いていればすぐ鳴らす**(2026-10-18)。待っている間は「鳴らした」扱いにしないので、たとえば 15km/h で脇見を始め、見たまま 25km/h へ加速すれば、20km/h を越えた時点で鳴る。監視不能も同じ

### 3-3. 運行の終了

- 「運行終了」は **2秒長押し**(誤操作防止)
- 終了時に監視時間(`monitoringMs`)と有効監視時間(`validMonitoringMs`、品質有効なフレームの時間)を記録する
- **異常終了した運行の片付け(SES-007)**: アプリ起動時に1回、起動より前に始まって終了処理されていない運行(`ACTIVE`)を片付ける

| その運行の発報記録 | 処理 |
|---|---|
| 1件以上ある | 状態を `ABORTED` にして残す。終了時刻 = 最後の発報の終わり(開始時刻より前にはしない)。監視時間は 0 のまま |
| 無い | 運行の行を削除する |

診断CSV・参考録画は削除しない。

## 4. 較正

### 4-1. 開眼較正(正面を見る)

- 時間: **10秒**(`calibrationDurationMs`)
- 品質無効のフレーム(顔なし・暗い・低fps など、§5)は使わない
- 有効フレームが **60枚**(`calibrationMinValidFrames`)未満なら失敗
- **同じフレームを2回数えない**(2026-10-18)。時刻が前のフレームより新しいものだけを使う。カメラが止まると枚数が増えないので、止まったまま較正が通ることはない(閉眼較正も同じ)
- 有効フレームの**中央値**を基準にする: yaw・pitch・roll・左右の開眼度・顔の大きさ
- 較正値は端末に保存する。取付を変えたら再較正が必要

### 4-2. 閉眼較正(目を閉じる)

目を閉じたときの正規化開眼比を測り、その人の閉眼閾値を決める。

| 項目 | 既定 |
|---|---|
| 基本時間 | **3秒**。安定区間が取れなければ **6秒**まで自動延長、取れなければ失敗 |
| 安定区間 | 直近 **1.5秒**、有効フレーム **15枚**以上、四分位範囲 **0.12** 以下 |
| 閉眼値 | 安定区間の正規化開眼比(左右平均)の中央値 |
| 失敗条件 | 開との差(1.0 − 閉眼値)が **0.30** 未満(目を閉じていない / サングラス等で瞼が読めない) |
| 閾値 | **閉眼値 + 0.30 ×(1.0 − 閉眼値)**(閉側に寄せる。PERCLOS の考え方) |
| クランプ | **0.35〜0.85**。かつ閉眼値 + **0.05** 以上 |
| 注意表示 | 開との差が **0.40** 未満なら「取れたが不安定」(較正は通す) |

閉眼較正が無いときの閾値は **0.45**(`eyeClosedOpenRatioThreshold`)。
開始と終了は音と短い振動で知らせる(目を閉じているため)。

## 5. 信号品質

1フレームごとにフラグを立て、スコア(1.0 から減点)を計算する。

| フラグ | 条件 | 減点 | facialSignalReliable |
|---|---|---|---|
| `NO_FACE` | 顔が検出されない | スコア 0 | — |
| `FACE_TOO_SMALL` | 顔の幅 < 画面幅の **20%** | 0.4 | 影響しない |
| `FACE_TOO_LARGE` | 顔の幅 > **60%** | 0.4 | 影響しない |
| `ONE_EYE_ONLY` | 相対 \|yaw\| > **30°** | 0 | **false** |
| `HEAD_ANGLE_TOO_LARGE` | 相対 \|yaw\| > **60°** または \|pitch\| > **70°** | 0 | **false** |
| `HEAD_ROTATING_RAPIDLY` | 頭部の合成角速度 > **45°/s** | 0 | **false** |
| `LOW_LIGHT` | 画面の平均輝度 < **40** | 0.35 | 影響しない |
| `LOW_FPS` | 解析 fps < **10** | 0.3 | 影響しない |
| `THERMAL_DEGRADED` | 端末の thermal status ≥ MODERATE | **0**(2026-10-17。記録のみ。室温でも MODERATE〜SEVERE を返す端末があるため) | 影響しない |

- **validForDecision = スコア ≥ 0.70 かつ NO_FACE でない**
- 横向き・回転のフラグは減点しない。横を向いていても**頭部角度は脇見の信号そのもの**なので、判定から外すと脇見が成立しなくなる(2026-09-01 の実測)。表情だけを信用しない(facialSignalReliable)
- **誤検出の除外(2026-09-27)**: 較正時の顔の大きさの **0.7倍**(`faceSizeSuspectRatio`)未満の検出は、validForDecision を false として扱う。横を向いている最中に「小さく・正面向き」の誤検出が出て、監視不能のタイマーを戻していたため。較正が無いときは適用しない

## 6. 判定と発報条件

### 6-0. 共通

- **継続時間**は、条件が真のフレームの連続時間。途切れても **500ms** 以内に戻れば継続。超えたらエピソード終了(0 に戻る)
- **cooldown(閉眼・こっくり・あくび・高温)**: 同じ種類を鳴らしてから **10秒**は、同じ重さ以下を鳴らさない。**より重い段階への昇格(注意 → 強い警告)は cooldown 中でも鳴らす**。同じエピソードの中では同じ重さを2度鳴らさない
- **cooldown(脇見)**: 方向ごとに持つ(§6.2)
- 発報は**運行中(MONITORING)だけ**。故障(§6.7)だけは前検査中も報知する

### 6-1. 長い閉眼

| 項目 | 条件 |
|---|---|
| 閉眼フレーム | validForDecision かつ facialSignalReliable かつ **左右の正規化開眼比の平均 ≤ 閾値**(閉眼較正の値。無ければ 0.45) |
| 注意(CAUTION) | 閉眼が **1.5秒** 継続 |
| 強い警告(WARNING) | 閉眼が **2.5秒** 継続 |
| 速度ゲート | 掛けない(停車中も判定する) |
| cooldown | 10秒(§6-0)。**直前の警告から10秒以内の別の閉眼は鳴らない**(2026-09-27 に「このままでよい」と確認済み) |

- 未較正の間は閉眼を判定しない
- 横を向いている・頭が速く動いているフレームは閉眼とみなさない(開眼度が実際と乖離するため)
- 左右の**平均**で判定する(片目だけ感度が低い人で AND 判定が機能しなかったため)
- 下を向くと瞼が下がり、開眼比が下がる。2026-09-27 の試験で、下を向いただけで CAUTION が出た(既知の誤報、§13)

### 6-2. 脇見(長い道路外注視)

#### (a) 脇見フレーム

- 相対 \|yaw\| ≥ **25°**、または相対 \|pitch\| ≥ **20°**(上下どちらも。符号は区別しない)
- validForDecision のフレームであること(facialSignalReliable は見ない)
- または**顔を見失っている間の脇見**((c))

#### (b) 発報までの時間

| 条件 | 継続時間 |
|---|---|
| 速度 > **50km/h** | **3.5秒**(EU ADDW に合わせる) |
| それ以外(速度不明を含む) | **6秒** |

継続時間は**全方向の合計**で数える。正面に戻らずに左右を見回し続けても、合計が基準に達すれば鳴る。
継続時間は**速度に関係なく**数える(2026-10-01、UN R183 5.5.2.3 の考え方。速度ゲートは警告だけを止める。(e))。

#### (c) 顔を見失った間の脇見(2026-09-27)

大きく横を向くと顔の検出が外れる(マスク着用では約25〜30°、着用なしでも片側で約50°)。

| 項目 | 条件 |
|---|---|
| 開始 | 見失う**直前の有効フレームの相対 \|yaw\| ≥ 15°**(`distractionCarryEntryYawDeg`)、または**相対 pitch ≥ 15°(下向き)**(`distractionCarryEntryPitchDownDeg`、2026-10-01) |
| 継続 | 見失っている間(validForDecision が false の間)は脇見として数える |
| 終了 | 有効フレームが戻ったとき、または見失ってから **15秒**(`distractionCarryMaxMs`)を超えたとき |
| 上限を超えたら | 脇見扱いを打ち切り、**見失った時点から数えた監視不能**として扱う(=超えた瞬間に「顔を確認できません」) |
| 方向 | 見失う直前の向き。下向きの外れ(15°に対する比)が横向きより大きければ `PITCH_PLUS`、それ以外は yaw の符号 |

下向きの見失いは 2026-10-01 に追加した(膝・足元を見ると顔を見失い、監視不能になっていた。手元は UN R183 の主な対象)。
15°は実機の診断CSV 50本で試算: 実車の見失い522回で追加発報0件、机上で意図的に下を見た3回(直前17〜33°)はすべて拾える。
上向きの見失いは対象外。

#### (d) 方向と cooldown(2026-09-27)

方向は4つ(+ 角度不明)。**左右・上下の名前ではなく角度の符号で持つ。**

| 方向 | 意味 |
|---|---|
| `YAW_PLUS` / `YAW_MINUS` | 横向き。左右との対応はカメラの鏡像・取付回転で変わる |
| `PITCH_PLUS` | **下向き**(前面カメラで 2026-09-27 に実測) |
| `PITCH_MINUS` | 上向き |

- 斜めを向いたときは、閾値(25° / 20°)に対する外れが大きい軸で決める
- 見失っている間は、見失う直前の方向

#### (d2) 手元と側方(2026-10-01)

UN R183 が警報の対象にするのは**手元**(Area 3:眼の基準点から下方30°より下、左右55°以内、窓を除く)だけで、側方は対象外(R183 0.4)。
脇見フレームを頭部の向きで次の2つに分ける(視線は未使用)。

| 領域 | 条件 |
|---|---|
| 手元 `HAND` | 相対 pitch ≥ **10°(下向き、暫定)**(`distractionHandMinPitchDownDeg`)かつ 相対 \|yaw\| ≤ **55°**(`distractionHandMaxYawDeg`) |
| 側方 `SIDE` | それ以外(真横・上向き) |

- 右ハンドル車のナビ・空調・シフトは「左へ20〜35°+やや下向き」なので、yaw だけで分けると側方に入る。そのため2軸を組み合わせて判定する
- **標準(`distractionSideEnabled` = true)では両方を数える**。警告の挙動は従来と同じで、分類は診断CSVの `distractionZone` に記録するだけ
- `distractionSideEnabled` = false では**手元だけを数える**(設定画面からは変えられない。コード上の設定)。数えない側方で顔を見失ったときは監視不能を止めない
- 10°は推測の暫定値。視線を加えるときに実データで決め直す

発報の手順(`shouldFireDistraction`):

1. 合計の継続時間が基準((b))に達している
2. そのエピソードでまだ鳴らしていなければ → いまの方向が cooldown 中でなければ鳴らす
3. 既に別の方向で鳴らしていれば → **いまの方向が単独で基準時間続き**、かつ cooldown 中でなければ鳴らす(振り向いた瞬間には鳴らさない)
4. 同じエピソードの中で同じ方向は2度鳴らさない

鳴らしたら、その方向の cooldown を **10秒**にする。**他の方向の cooldown には影響しない。**

| 例(基準6秒・cooldown 10秒) | 結果 |
|---|---|
| 右6秒 → 正面 → 右6秒(10秒以内) | 2回目は鳴らない |
| 右6秒 → 正面 → 左6秒(10秒以内) | **左も鳴る** |
| 右6秒 → 正面に戻らず左へ | 左が単独で6秒続いたら鳴る |
| 右2秒 ↔ 左2秒を正面に戻らず繰り返す | 合計6秒で1回鳴る |

#### (e) 速度ゲート

- 速度 **< 10km/h** の間は脇見を**鳴らさない**(信号待ち・休憩・積卸しの誤報を消すため)
- **継続時間は速度に関係なく数える**(2026-10-01)。停車中から見続けたまま発進すると、速度が 10km/h を越えた最初のフレームで鳴る。実車の診断CSV(約14時間)で試算すると、これで新たに鳴る場面は1件(低速から18km/hへの加速中)
- **速度が取れない間(測位前・トンネル・権限なし)は判定する**(安全側)
- **速度は最後の測位から 3秒以内のものだけ使う**(2026-10-18)。測位が途絶えた・位置情報がオフにされたときは速度不明として扱う。古い 0km/h が残り続けて脇見を止め続けないため
- 動作確認モード(`testModeIgnoreSpeedGate`)が ON なら常に判定する。ON の間は画面に常時表示する
- 記録用に、手元・側方を区別しない継続時間(`distractionRawDurationMs`)も診断CSVに残す(側方を数えない設定のときだけ `distractionDurationMs` と異なる)

### 6-3. こっくり

頭部の反復的な上下動。

| 項目 | 条件 |
|---|---|
| 反転 | 相対 pitch が直近の極値から **5.0°** 以上戻ったら1回(ZigZag 法) |
| 成立 | 直近 **12秒**の反転が **5回**以上、**かつ**同じ窓の平均正規化開眼比 ≤ **0.75** |
| 入力 | validForDecision かつ facialSignalReliable のフレームだけ |
| あくびの抑制 | jawOpen ≥ **0.60** の間とその後 **1秒**は、反転・開眼比を数えない(あくびの頭の動きを数えないため) |
| 報知 | 注意(CAUTION)。成立が途切れたら次を鳴らせる。cooldown 10秒 |

**開眼こっくり候補**(音も画面も出さない。記録だけ): 反転5回以上、かつ窓内の pitch の振れ幅 ≥ **20°**、かつ yaw の振れ幅 < **10°**。本物のこっくりが同時に成立しているときは記録しない。

### 6-4. あくび

| 項目 | 条件 |
|---|---|
| 1回の成立 | jawOpen ≥ **0.45** が **1.5秒**以上連続、**かつ**その区間の jawOpen の最大値 ≥ **0.60** |
| 連続の判定 | 口が閉じた(値あり・閾値未満)らその場で終了。値が取れない(品質無効)のは 500ms まで保留 |
| 報知 | 直近 **10分**に **3回**以上で注意(最も弱い音) |
| 繰り返し | 頻発の間は、あくびが1回成立するたびに鳴らせる(cooldown 10秒) |
| 入力 | validForDecision かつ facialSignalReliable のフレームだけ |
| 運行またぎ | **あくびの成立時刻だけ次の運行へ引き継ぐ**(眠気は運行の区切りと無関係に続くため)。10分より古いものは捨てる。進行中の開口は引き継がない |

- 較正を使わない絶対値で判定する
- **マスク着用時は jawOpen が 0 のままで、あくびは検知できない**(2026-09-27 実測)

### 6-5. 監視不能

判定に使えるフレームが来ない状態。**システムは動いている**(故障とは別)。

| 状態 | 条件 |
|---|---|
| LIMITED | 品質無効が **2秒** 継続 |
| UNAVAILABLE | 品質無効が **5秒** 継続。「顔を確認できません」を報知 |
| 繰り返し | UNAVAILABLE が続く間、**10秒**ごとに報知を繰り返す(`unavailableRepeatMs`、0 で無効)。**音だけで、DB記録は最初の1回** |
| NORMAL へ復帰 | 品質有効が **1秒** 継続 |
| 一瞬の回復 | 品質有効が **500ms 未満**なら、監視不能までの計測を戻さない(2026-09-27) |
| 脇見との関係 | 顔を見失った間を脇見として数えている間は、監視不能へ進めない(5秒の監視不能が6秒の脇見より先に鳴るのを防ぐ)。**ただし速度ゲートが閉じている(停車中)ときは止めない**(脇見が鳴らない状況で監視不能まで止めると無音になるため) |

### 6-6. 高温

- thermal status が **SEVERE 以上**、**かつ運行中の最低値より上**で注意
- 端末によっては冷えていても SEVERE を返す(Nothing Phone (2a) で確認)ため、絶対値では判定しない
- cooldown 10秒。一旦下がれば次を鳴らせる

### 6-7. 故障(ASV 眠気4章・脇見4章の必須要件)

0.5秒ごとに評価する。**画面が見えている間(Activity が STARTED)だけ**評価し、見えるようになるたびに状態を作り直す(起点は残す。起点を消すと、カメラが一度もバインドされないとき故障が永久に報知されない)。

| 故障 | 条件 | 表示 |
|---|---|---|
| `CAMERA_UNAVAILABLE` | カメラのバインドに失敗 | カメラを開けません |
| `INFERENCE_FAILING` | 推論エラーが **10回**連続 | 解析が繰り返し失敗しています |
| `NO_FRAME` | フレームが **3秒**届かない。起動中(まだ1枚も届いていない)は **10秒** | カメラ映像が届きません |
| `NO_RESULT` | フレームは届くのに結果が **3秒**返らない。起動中は10秒 | 解析結果が返りません |

- 故障になった瞬間に1回だけ音(監視不能と同じ音)と振動。故障が続く間は赤帯を出し続ける
- 赤帯の文言: 「監視機能が使用できません(理由)」+ 「安全な場所でアプリを再起動してください」
- 運行中なら DB に `SYSTEM_FAULT` を記録する
- 評価を「見えている間」に限るのは、画面を消したときにカメラが止まるのは正常だから(2026-08-31)。一方、ダイアログ表示中や小窓(PiP)中は評価を続ける

## 12. 既定値一覧

「画面」列: ◎ = 閾値設定画面のスライダーで変えられる(**10項目**)、— = 画面からは変えられない(コード上の設定)。

閾値設定画面は、わかりやすさを優先して次の10項目だけをスライダーで出す。各項目に説明文・既定値・「敏感 ↔ 鈍感」の向きを添える。
閉眼を2段階にする2項目は、**強い警告が注意より500ms以上長くなるよう**自動で揃える。脇見の「警告まで」を短くしたときは、時速50km超の警告時間(既定3.5秒)も、それ以下に揃える。

| 区分 | 項目(設定名) | 既定 | 画面の範囲(刻み) |
|---|---|---|---|
| 閉眼 | 注意まで(`eyeClosureCautionMs`) | 1.5秒 | ◎ 0.5〜3.0秒(0.1) |
| 閉眼 | 強い警告まで(`eyeClosureWarningMs`) | 2.5秒 | ◎ 1.0〜5.0秒(0.1) |
| こっくり | 警告に必要な反転回数(`noddingMinReversals`) | 5回 | ◎ 3〜8回(1) |
| あくび | 注意に必要な回数(`yawnMinCountInWindow`) | 3回 | ◎ 1〜6回(1) |
| あくび | 回数を数える期間(`yawnWindowMs`) | 10分 | ◎ 5〜30分(5) |
| 脇見 | 警告まで(通常)(`distractionWarningMs`) | 6秒 | ◎ 2〜10秒(0.5) |
| 脇見 | 横向きの角度(`distractionYawDeg`) | 25° | ◎ 15〜45°(1) |
| 脇見 | 上下向きの角度(`distractionPitchDownDeg`) | 20° | ◎ 10〜40°(1) |
| 脇見 | 判定する速度の下限(`distractionMinSpeedKph`) | 10km/h | ◎ 0〜30km/h(5) |
| 共通 | 同じ警告の間隔(cooldown)(`alertCooldownMs`) | 10秒 | ◎ 5〜30秒(5) |

次の項目は画面から変えられない(既定値のまま)。

| カメラ | インカメラのズーム(`frontCameraZoomRatio`)。詳細 → カメラで 1.0 / 1.25 / 1.5倍。変えると較正を消す | 1.0倍 |
| 品質 | 誤検出とみなす比率(`faceSizeSuspectRatio`) | 0.7 |

| 品質 | 角度上限 yaw / pitch | 60° / 70° |

| 品質 | 最低 fps(`minValidFps`) | 10 |
| 品質 | 品質有効の閾値(`qualityValidThreshold`) | 0.70 |
| 品質 | 頭部角速度の上限 | 45°/s |
| 較正 | 較正時間 / 必要な有効フレーム | 10秒 / 60枚 |
| 閉眼 | 閉眼とみなす開眼比(較正なしのとき) | 0.45 |
| 脇見 | 警告まで(50km/h 超) | 3.5秒 |
